# Grid Granularity Tuning: Benchmark Results and Optimal Value Selection

This document presents the experimental results for choosing the optimal `grid_granularity_k` parameter in the parallel block‑based image convolution.

**Definition:**  
`N = grid_granularity_k × T`  
- `N` – number of rectangular blocks  
- `T` – number of OpenMP threads  

The goal was to find the value of `grid_granularity_k` that minimises execution time for images of different sizes.

## Analysis

| Image size (h × w)     | Best `grid_granularity_k` | Time (s) | Observations                                                      |
| ---------------------- | ------------------------- | -------- | ----------------------------------------------------------------- |
| 4320 × 7680 (large)    | **1**                     | 0.6745   | Time increases for `k > 1` – overhead from many blocks dominates. |
| 2160 × 3840 (medium)   | **1** (or 9)              | 0.2183   | All values close; `k=1` is among the fastest.                     |
| 339 × 569 (small)      | **1**                     | 0.006627 | No significant variation.                                         |
| 120 × 300 (very small) | **1**                     | 0.001387 | No significant variation.                                         |

## Key Observations

- For the **largest image** (4320×7680) the best performance is achieved with `grid_granularity_k = 1`.  
  Increasing the granularity (more blocks per thread) leads to higher execution times – likely due to additional scheduling overhead and worse cache locality.

- For medium and small images the differences are marginal, and `k = 1` always remains a safe, near‑optimal choice.

## Conclusion

**Optimal value: `grid_granularity_k = 1`** for all tested image sizes.
